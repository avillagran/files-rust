# Toolkit 9210589: context menu with submenus

User request (2026-11-05): «El menú con botón derecho es exageradamente
largo, deben estar agrupados en submenús» (the right-click menu is far too
long; it should be grouped into submenus). The submenus come from the toolkit
(lib-fltk-omarchy `9210589`, GitHub main, no tag); Files does not patch the vendor.

## Vendor

- `vendor/lib-fltk-omarchy` is the exact export of `9210589` (verified
  byte for byte) plus `UPSTREAM.json`.
- Do not use `cargo fmt --all`: it reformats the vendor. Format only the Files
  crates (`cargo fmt -p files-ui -p files-core -p files-app -p files-helper`).

## Menu

The flat list in `context_menu::Menu` is still the single source: it is used in
the menu drawn by Files and in the tests. `context_menu::layout`/`place`
only decide where each entry goes, based on its action. An entry without a rule falls
into «Más ›» (More); it never disappears, and there is a test for that.

- Files: Open, Open with…, Preview │ Cut, Copy, Paste │
  Rename, Trash │ Clipboard ›, Organize ›, Compress ›, Selection ›,
  Terminal here │ Properties. That is 14 rows; before there were about 35 counting the
  headings.
- Background: Create folder, Create file, New document › │ Paste,
  Paste special › │ Show hidden, Refresh │ Select ›,
  Tools ›, Device ›.
- Each leaf carries `.id(<flat index>)` and the menu opens with `open_at_id`.
  `on_pick` runs before `on_dismiss`, so Files activates the chosen flat
  entry whether or not it is in a submenu. `Dismiss::Picked` still returns the root row.
- The Nerd glyph in the text moves to the icon column so leaves and
  submenus stay aligned.

## Verification

- Unit tests: each entry is placed exactly once, the root has at
  most 14 rows, and Rename, Trash and Copy stay in the root.
- `scripts/toolkit-menu-ui-check.py` (Xvfb, `OMARCHY_FLTK_ANIM=off`): walks
  Selection › Invert with the keyboard (Down, Right, Enter), checks
  `Picked(root row)` and that Files ran the flat entry. It saves a capture of the
  open submenu.
- Also: toolkit-input, toolkit-visual, nautilus-floor, hidden-context,
  preview-copy-nested and the full suite (812/720/112), with Clippy.
  popup-media failed once («no ready thumbnail observed») right after the
  suite and passed in the 5 remaining runs; the failure evidence is kept.
- Toolkit behavior changes: Space now activates the entry just like
  Enter, and menus fit to the window, not to the monitor.
